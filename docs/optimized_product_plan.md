# LitAudit 优化方案（v0.2）

> 目标：把 LitAudit 从“功能齐全的演示原型”收敛为“可信、可复现、可评测的文献审计产品”。
> 本方案优先解决效果可信度和闭环验收，不继续无边界增加 UI 或 Agent 数量。

## 1. 产品重新定位

LitAudit 不承诺自动完成一篇综述，也不直接判断某个研究想法“绝对新颖”。它输出的是一份**带证据等级的研究决策包**：

1. 检索是否充分、哪些来源失败；
2. 哪些论文纳入、排除或待核验，以及理由；
3. 哪些论断得到什么级别的证据支持；
4. 哪些论文可能反驳当前想法；
5. 哪些结论仍然不能下定论。

产品首页的主结果应是“证据状态与下一步建议”，长篇自然语言总结降为辅助视图。

## 2. 首期必须收敛的范围

首期只支持一个垂直问题族：LLM agent / RAG 在科学文献问答与自动综述中的效果和可信度。

支持三类任务：

- 领域摸底：找主线、代表论文和争议；
- 想法查新：找同构工作、强基线和反证论文；
- 论断核验：逐句检查已有文本是否被原文支持。

明确不承诺：跨学科综述、因果元分析、全自动投稿稿件、完整引用图谱、未经全文核验的页码证据。

## 3. 可信度优先的目标架构

采用“确定性流水线 + LLM 辅助”的结构，而不是让 Agent 自由编排：

```text
输入问题
  -> 范围确认（结构化）
  -> 查询计划（可编辑、可版本化）
  -> 多源召回与缓存
  -> 去重与候选筛选
  -> 全文获取/解析（失败可降级）
  -> 证据片段抽取
  -> Claim-Evidence 判决
  -> 冲突与反证分析
  -> 带状态的研究报告
```

每个阶段都必须落盘一个版本化对象，并记录 `run_id`、输入哈希、模型、提示词版本、时间和失败原因。LLM 只能提出候选字段或判决，规则校验器负责拒绝非法状态。

## 4. 数据契约升级

在现有 `PaperCard / Claim / Evidence` 之外，增加以下概念：

- `ResearchQuestion`：对象、方法/现象、任务、比较基线、时间窗、领域边界；
- `QueryPlan`：查询词、来源、目的、版本和覆盖的子问题；
- `SourceSnapshot`：原始响应、HTTP 状态、内容哈希、抓取时间；
- `EvidenceSpan`：文档版本、页码/章节、段落哈希、摘录文本；
- `DecisionTrace`：判决所依据的证据、规则结果、模型结果和冲突状态；
- `NextAction`：建议补检索、补全文、人工复核或接受当前不确定性。

状态规则统一为：

- 证据层：`verified / abstract_only / unverified / failed`；
- 论断层：`supported / partial / unsupported / pending`；
- 检索层：`success / partial_failed / all_failed / rate_limited`。

任何 `supported` 必须满足：至少一条可定位支持证据、无未解决反证、规则与模型没有冲突。否则自动降级为 `partial` 或 `pending`。

## 5. 检索与筛选优化

### P0

1. 查询计划由用户可见，按“主问题、同义词、反向词、边界词”分组；
2. 每个来源独立显示成功、零结果、限流和失败；
3. DOI、arXiv ID、标准化标题三层去重，并保留合并历史；
4. 筛选采用“规则初筛 -> LLM 复核 -> 不一致进入 pending”；
5. 新主题不得复用旧主题的默认筛选器和论文集合。

### P1

1. 对纳入论文优先获取 PDF 或开放全文；
2. 记录全文获取失败的可恢复原因；
3. 增加人工修订筛选结果的审计记录；
4. 对检索覆盖率做子问题矩阵，而不是只看总论文数。

## 6. 证据与回答优化

回答分为三层：

1. **确定事实**：只来自 `verified` Evidence；
2. **摘要级线索**：明确标记 `abstract_only`，不得写成确定结论；
3. **待核验建议**：说明缺什么证据以及下一步怎么查。

所有自然语言句子在生成前先绑定 Claim ID；生成后执行引用完整性检查。发现没有 Claim、没有 Evidence 或定位失效时，句子不得进入确定结论区。

对话路由应优先复用当前 run；只有新主题、扩大范围、分支深入或明确重新检索才创建新 run。LLM 不可用时只报告服务状态，不生成虚构结论。

## 7. 研究地图优化

地图分成两种模式，避免混淆：

- **证据图**：只画已落盘的支持、冲突和反证关系；
- **主题图**：画摘要级主线和相似关系，并在视觉上标注“启发式”。

没有真实引用数据时，不得把主题相似边称为引用关系。每条边都显示来源、证据级别和生成规则。

## 8. 评测重做为可验收的指标体系

评测拆成四组，分别报告均值和逐题结果：

1. **检索**：子问题 Recall@k、去重准确率、失败状态识别率；
2. **筛选**：include/exclude precision、recall、pending 校准率；
3. **证据**：引用存在率、Evidence 定位率、Claim 支撑准确率、冲突保留率；
4. **反证**：杀手论文 Recall@k、威胁等级一致率、误报率。

必须增加人工双人标注的小测试集和盲评协议。仓库内 gold 只能证明回放链路，不得单独宣称模型效果提升。至少设置三个对照：关键词检索、普通 RAG、无外部检索 LLM；统一题目、预算和候选上限。

## 9. 分阶段交付

### Phase 0：冻结契约（1 天）

- 冻结 `ResearchQuestion / QueryPlan / EvidenceSpan / DecisionTrace` 字段；
- 写状态机和非法状态测试；
- 固定 3 个评测题及人工金标准。

### Phase 1：可靠离线闭环（2–3 天）

- 用真实 PDF 和固定缓存完成一次完整 run；
- 每条结论都能回到页码；
- UI 显示所有失败、pending 和排除项；
- `pytest`、`doctor`、`validate`、`evaluate` 全通过。

### Phase 2：在线增量检索（2–3 天）

- 三来源独立状态；
- 新 run 隔离；
- 在线论文默认只到摘要级；
- 全文缺失不得升级为 verified。

### Phase 3：效果增强（3–5 天）

- 全文解析和证据片段召回；
- LLM/规则双判决；
- 人工复核入口；
- 评测结果按题目和模块出表。

### Phase 4：交付验收（1 天）

- 录制一条 8–10 分钟离线演示；
- 导出审计报告；
- 检查密钥、数据、run、限制说明；
- 只宣传已被评测支持的能力。

## 10. 当前项目的优先级排序

### P0（必须先做）

- 修复在线来源适配和错误状态的一致性；
- 补齐全文获取/解析失败的结构化状态；
- 实现句子到 Claim 的引用完整性检查；
- 增加人工金标准和真实对照实验；
- 删除或降级任何容易让用户误以为“已完成全文审阅”的文案。

### P1（随后做）

- 引入查询计划和覆盖矩阵；
- 增加人工筛选/证据复核操作；
- 改进反证检索排序和威胁等级校准；
- 将主题图和证据图分开。

### P2（最后做）

- 引用网络、聚类算法和更复杂的可视化；
- 多学科扩展；
- Arbor 或其他实验系统的联动。

## 11. 终验标准

只有同时满足以下条件，才称为“完成首期优化”：

1. 任一确定结论可沿 `Claim -> EvidenceSpan -> Paper -> SourceSnapshot` 回溯；
2. 检索失败、限流、零结果三者在数据和 UI 中可区分；
3. 正反证据冲突时不会输出 `supported`；
4. 在线新论文没有全文证据时不会伪装成页码级核验；
5. 三个评测题在固定预算下可重复运行，并有人工对照；
6. 新主题不会污染旧 run；
7. 离线演示、测试和审计报告可在干净环境复现。

## 12. 产品判断原则

宁可输出“证据不足、需要复核”，也不要输出流畅但无法核验的结论。LitAudit 的竞争力不是论文数量或文字长度，而是让研究者知道：**哪些可以相信、为什么可以相信、哪里还不能相信。**
