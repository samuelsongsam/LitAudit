# 有界研究执行层实施计划

## 交付范围与原则

以 lhk 完整实现为基础，合入 sxt；保留当前摘要综述修复。金标目录只读。
第一版是显式开启的全文补证试点，不替代普通聊天、检索和导出。
暂不开放任意 URL、Shell、文件路径、人工判决或删除工具，也不开放自动扩大文献检索范围。

## 实施步骤

1. 整合基础：接纳 lhk 的全文工作区、后台任务、取消与超时机制，检查全部冲突和依赖。
2. 对话身份：为旧记录提供兼容的 conversation_id，新记录和延续快照保留同一身份；侧栏按身份去重，API 返回稳定身份与当前 run_id。不按同名标题合并历史。
3. 工具协议：Pydantic 严格验证工具名称、参数、论文白名单与数量；工具只接受当前研究的论文 ID。
4. 执行循环：模型每次选择一个动作，工具结果反馈后可继续选择；最多 4 次动作决策、最多 1 次全文获取（最多 2 篇），总补证墙钟时间 90 秒。相同动作立即停止，完成、预算、非法参数、错误均有独立状态。
5. 执行隔离：耗时工具放入可终止子进程，复用现有 transport 的截止时间与取消控制；敏感配置不写轨迹。下载与解析仍执行已有网络和文件校验。
6. 持久化：每步执行前后保存轨迹；同一请求复用完成结果。服务崩溃时未确认完成的写入动作不自动重放，返回 interrupted，用户新发请求前可检查已保存快照。
7. 交互：聊天提供显式“自动补充全文依据”选项，默认关闭；执行结果交给现有材料综述和引用核验，不接受规划器直接生成的研究事实。
8. 回归：范围隔离、重复动作、预算、非法参数、超时、取消、模型/工具失败、重启后不重复写入、对话延续，以及原有全部 Python/前端回归。
9. 提交：检查差异与敏感文件，按本次授权提交并推送至 GitHub sxt，禁止强制推送。

## 验收与边界

- 普通聊天不增加 Agent 调用；关闭试点即可恢复固定流程。
- 工具失败不伪装成无论文；已有摘要仍可用于回答，执行状态另行展示。
- 全文快照与对话分别标识，重复点击不重复下载。
- 不保证跨崩溃精确一次执行：不确定的写入禁止自动重放，以避免重复副作用。
- 90 秒预算覆盖补证循环，不含之后已有回答与复核流程；每轮模型 max_tokens=1200。
- 试点不声明真实效果提升：先用模拟故障与回归验证机制，再人工对照真实问题的完成率、引用正确率、延迟和费用。
- 跨进程工具被终止后可能留下未完成研究副本，原始材料不变；通过任务/快照状态检查，不自动删除。

## 后续扩展门槛

只有全文补证试点改善实际完成率、且无范围和引用退化后，才增加论文搜索工具与查询改写。
多来源检索要另设请求预算、来源失败类型和可重复评测集，不与第一版同时扩张。

## 本次实现与验证记录

- 已接纳 lhk 基础并保留摘要综述模块，接入显式试用开关。
- 工具执行采用受限 JSON 动作协议（不是 SDK 原生 tool_calls）；规划、执行和回答核验分离。
- 已实现严格参数校验、当前研究白名单、步骤/下载预算、子进程截止时间、取消、每步落盘、重复请求结果缓存。
- conversation_id 为兼容旧记录的稳定逻辑身份；run_id 继续负责定位研究材料。侧栏按身份合并，不按标题猜测。
- 同一请求的响应也缓存，防止重复模型回答和重复保存消息。
- 全量 Python 回归：579 项通过；后续新增真实子进程、接口及响应缓存测试后，相关回归 85 项通过。
- 前端覆盖试用开关、稳定请求 ID、强制新检索时关闭 Agent，以及原有工作台回归。
- 未进行真实模型效果、外部全文服务成功率或费用对照评测；模拟测试不能代替这些指标。
- 并发去重锁目前适用于单服务进程；不支持多个服务实例同时写同一 runs 工作区。生产多实例部署前需增加跨进程协调。
